# Research Note — git-activity

**Repo:** https://github.com/kleinpanic/git-activity
**Problem:** Produce a deterministic, reproducible backdated-commit generator that draws patterns on the GitHub contribution graph.

## Goal

The current repo state is 2,373 commits (1 init + 2,372 gradient) across a 365-day linear ramp from 1 commit/day to 12 commits/day. The commits were generated by a one-off script, but the script itself was never committed. This is a concrete reproducibility problem: if the script is lost, no one (including future tooling) can regenerate the gradient, audit it, or extend it to other patterns.

The new CLI is the fix. It captures the gradient logic, plus two derived modes (text in a 5x7 bitmap font, and draw from a 7-pixel-tall PNG).

## Pre-existing state

- `git log` shows 2,373 commits ending with `gradient 364-11` on 2026-08-04.
- Author email is `165743429+kleinpanic@users.noreply.github.com` (the noreply email linked to the GitHub account, so commits count toward the profile graph).
- Working tree before this change: `README.md` tracked, plus 2,372 `c_DAY_IDX.txt` files committed at the time of their backdated timestamps. The `scripts/`, `tests/`, `pyproject.toml`, `requirements.txt`, and `.gitignore` are untracked.

## Design choices

### Why three modes?

The original generator only produced a gradient. Adding `text` and `draw` is a small addition that generalizes the tool: any bitmap that fits 7 rows tall (the GitHub graph is 7 rows = Sun..Sat) is now consumable. The text mode is a teaching example; the draw mode is a power-user trigger.

### Why a 5x7 bitmap font?

A 5x7 font maps cleanly to the 7-row graph (each glyph row = one graph row). Hand-rolled glyphs are kept inline in `font_5x7.py` because there is no acceptable dependency for what is essentially 37 small bitmaps. Each glyph is 7 strings of 5 binary characters.

Letters are concatenated with a 1-column blank space, so `KLEIN` is 5×5 + 4×1 = 29 columns. Any column that ends up all-zero is dropped from the plan (no commits on those days).

### Why a 7-row limit on draw mode?

GitHub's contribution graph is exactly 7 rows tall (Sun..Sat). The image must be 7 pixels tall. Width is unconstrained — the caller decides how many weeks they want to draw. The CLI places the rightmost column on the Saturday of the week containing `--end`, so the pattern is anchored to the user's end date.

### Why a per-day cap?

GitHub visually saturates the contribution graph at ~10-12 commits per day. Going beyond 12 produces no visual difference. The cap is applied as a single post-filter in `cap_counts()`, so every mode is capped the same way.

### Why unique salt per commit?

`commit.gpgsign=false` plus backdated timestamps means git will deduplicate commits whose tree hash matches. Adding `os.urandom(8).hex()` to each commit's content guarantees a unique SHA, which is what the original gradient uses (`c_000_00.txt` contains `salt=0-0-8df72905f74dd092`, for example).

### Why a separate `_commits.py` module?

Both `plan_text` and `plan_draw` produce a `dict[date, int]`. The materialization step (turning that dict into actual `git commit` invocations) is identical for all modes. Extracting it into `_commits.py` keeps the mode logic mode-specific and the commit logic DRY.

### Why are the historical committed `c_*.txt` files kept in the tree?

The artifacts of the original 2,372 gradient commits are small text files (~46-49 bytes each) and they are the actual commit contents. Removing them would rewrite the entire repo history. Keeping them is cheap (≈110 KB total) and preserves the existing graph.

## Validation evidence

- `python3 -m pytest tests/ -v` → 22 passed in 0.19s
- `python3 scripts/generate_gradient.py --mode gradient --start 2024-01-01 --end 2024-01-05` → renders the diagonal gradient preview, total commits = 32
- `python3 scripts/generate_gradient.py --mode text --text "KLEIN" --start 2026-07-11 --end 2026-08-04` → renders the bitmap text, total commits = 71

The text mode preview output was visually inspected to confirm the glyphs render correctly (K, L, E, I, N readable in the 7-row preview).

## What's not in scope

- No force-push, no history rewrite. The existing 2,372 commits stay as-is.
- No re-generation of the gradient. The repo's contribution graph is already populated.
- No CI pipeline. This is a one-shot generator CLI, not a long-running service.
- No remote-push of the new commits. They stay local until the user decides to push.
